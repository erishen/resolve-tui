# resolve-tui 架构文档

## 1. 架构概览

resolve-tui 是一个 CLI / TUI 双形态的编码 agent，采用**三级响应链**架构，从快到慢逐级降级：

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│                   三级响应链                              │
│                                                           │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────┐ │
│  │  fastpath    │───▶│   codegen    │───▶│ LLM 主循环│ │
│  │  (零模型)    │    │  (缓存命中)  │    │ (流式对话)│ │
│  └──────────────┘    └──────────────┘    └──────────┘ │
│         │                     │                     │     │
│         ▼                     ▼                     ▼     │
│    算术/单位/日期         确定性任务            复杂任务   │
│    直接返回结果           零模型返回           工具调用循环 │
└─────────────────────────────────────────────────────────┘
    │
    ▼
  输出结果（CLI 单次 / TUI 交互）
```

### 设计原则

- **渐进式复杂度**：简单问题用简单路径，复杂问题才调用 LLM
- **可插拔架构**：技能、MCP 服务器、codegen 插件均可动态扩展
- **安全隔离**：沙箱隔离代码执行，每任务独立工作区
- **隐私优先**：密钥仅存环境变量/钥匙串，会话/记忆不入库

## 2. 三级响应链详解

### 2.1 Fastpath（快路径）

**位置**：`src/fastpath/`

**职责**：纯代码可解的问题直接短路，零模型往返。

**支持的类型**：

| 模块 | 功能 | 示例 |
|------|------|------|
| `arithmetic.rs` | 算术运算 | `12345 * 6789` |
| `unit.rs` | 单位换算 | `100 km to miles` |
| `date.rs` | 日期计算 | `今天 + 30天` |
| `time.rs` | 时间处理 | `UTC+8 现在时间` |
| `statistics.rs` | 统计计算 | `平均值/中位数/标准差` |

**特点**：
- 零延迟，本地计算
- 确定性结果，可复现
- 无 API 调用，无成本

### 2.2 Codegen（代码生成缓存）

**位置**：`src/codegen/`

**职责**：命中已学习插件的确定性任务零模型返回；新任务用分层便宜模型生成代码并缓存。

**架构**：

```
用户输入
    │
    ▼
┌─────────────────┐
│  插件注册表      │  registry.rs
│  (已学习插件)    │
└────────┬────────┘
         │ 命中？
         ├─ 是 ──▶ 执行缓存代码 ──▶ 返回结果
         │
         └─ 否 ──▶ 检测器（便宜模型）
                        │
                        ▼
                   生成 Rhai 脚本
                        │
                        ▼
                   沙箱执行验证
                        │
                        ▼
                   存入缓存（learn 插件）
```

**核心组件**：

| 组件 | 文件 | 职责 |
|------|------|------|
| 引擎 | `engine.rs` | codegen 主流程调度 |
| 提取器 | `extract.rs` | 从输入提取参数和意图 |
| 插件注册表 | `plugins/registry.rs` | 管理已学习插件 |
| 缓存插件 | `plugins/cache.rs` | 插件持久化缓存 |
| 学习插件 | `plugins/learn.rs` | 新插件学习与保存 |
| 沙箱 | `sandbox.rs` | Rhai 脚本安全执行 |

**特点**：
- 首次调用用便宜模型生成，后续命中零成本
- Rhai 沙箱隔离执行，安全可靠
- 插件可持久化，跨会话复用

### 2.3 LLM 主循环

**位置**：`src/agent/`, `src/llm.rs`

**职责**：复杂任务通过 Responses API 流式对话，内置工具调用循环。

**架构**：

```
用户输入
    │
    ▼
┌─────────────────────────────────────────┐
│           Agent 主循环 (drive.rs)        │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │  1. 构建系统提示 + 历史消息       │   │
│  │     - 技能索引注入                │   │
│  │     - 沙箱工作区信息              │   │
│  │     - 可用工具列表                │   │
│  └──────────────┬───────────────────┘   │
│                 │                        │
│                 ▼                        │
│  ┌──────────────────────────────────┐   │
│  │  2. 调用 LLM (llm.rs)            │   │
│  │     - Responses API 流式请求      │   │
│  │     - 支持 OpenAI 兼容端点        │   │
│  │     - 重试/超时/用量统计          │   │
│  └──────────────┬───────────────────┘   │
│                 │                        │
│         ┌───────┴───────┐                │
│         │               │                │
│    工具调用？         最终回复？          │
│         │               │                │
│         ▼               ▼                │
│  ┌─────────────┐  ┌──────────┐          │
│  │ 3. 执行工具  │  │ 4. 返回  │          │
│  │  - shell     │  │   结果   │          │
│  │  - read_file │  └──────────┘          │
│  │  - write_file│                        │
│  │  - list_dir  │                        │
│  │  - MCP 工具  │                        │
│  └──────┬──────┘                        │
│         │ 结果回灌                        │
│         └────────────────────────────────┘
│                 │                        │
│                 ▼                        │
│         达到最大迭代？──是──▶ 终止        │
│                 │否                      │
│                 └────────────────────────┘
└─────────────────────────────────────────┘
```

**内置工具**：

| 工具 | 职责 | 权限 |
|------|------|------|
| `shell` | 执行 shell 命令 | 沙箱隔离 |
| `read_file` | 读取文件 | 读范围限制 |
| `write_file` | 写入文件 | 工作区限制 |
| `list_dir` | 列出目录 | 读范围限制 |
| MCP 工具 | 动态扩展 | 按服务器配置 |

## 3. PSE 三角色架构

**位置**：`src/agent/roles.rs`

**设计思路**：参考 `agentic-souls`，将复杂任务分解为三个独立角色，形成闭环验证。

```
用户目标
    │
    ▼
┌─────────────────────────────────────────────────────┐
│                  Planner (主 agent)                   │
│  职责：任务分解、步骤规划、调度 Specialist/Evaluator  │
│  工具：delegate_specialist + evaluate + 只读工具     │
│  限制：不能直接执行写操作                              │
└──────────────────────┬──────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
┌──────────────────┐      ┌──────────────────┐
│  Specialist      │      │  Evaluator       │
│  (子循环)         │      │  (子循环)         │
│                  │      │                  │
│  职责：执行任务   │      │  职责：独立验证   │
│  工具：完整工具集 │      │  工具：只读工具   │
│  含写操作         │      │  输出：PASS/     │
│                  │      │        PARTIAL/   │
│                  │      │        FAIL/       │
│                  │      │        BLOCKED     │
└────────┬─────────┘      └────────┬─────────┘
         │ 执行结果                  │ 验证结果
         └────────────┬─────────────┘
                      │
                      ▼
              Planner 汇总决策
                      │
            ┌─────────┴─────────┐
            │ PASS              │ FAIL/PARTIAL
            ▼                   ▼
        返回结果          重新规划/重试
```

**角色对比**：

| 角色 | 定位 | 工具权限 | 输出 |
|------|------|----------|------|
| Planner | 规划者 | 只读 + delegate + evaluate | 任务分解、调度决策 |
| Specialist | 执行者 | 完整工具集（含写） | 执行结果、代码、文件 |
| Evaluator | 验证者 | 只读工具 | PASS/PARTIAL/FAIL/BLOCKED |

**开启方式**：
- CLI：`--multi-agent` 或 `HARNESS_MULTI_AGENT=1`
- TUI：`/pse on|off`（下一轮生效）

## 4. 沙箱架构

**位置**：`src/sandbox.rs`

**设计目标**：隔离代码执行，保护本地文件系统，每任务独立工作区。

```
┌─────────────────────────────────────────────────────────┐
│                    沙箱根目录                              │
│  .resolve-tui-sandbox/  (HARNESS_SANDBOX_DIR 覆盖)      │
│                                                           │
│  ┌─────────────────────────────────────────────────┐    │
│  │  任务工作区 1 (task-<nanos>-<pid>/)             │    │
│  │  - write_file 写入此目录                          │    │
│  │  - shell workdir 设为此目录                       │    │
│  │  - 可写白名单 = 此目录                             │    │
│  └─────────────────────────────────────────────────┘    │
│                                                           │
│  ┌─────────────────────────────────────────────────┐    │
│  │  任务工作区 2 (task-<nanos>-<pid>/)             │    │
│  │  - 独立于工作区 1，互不影响                       │    │
│  └─────────────────────────────────────────────────┘    │
│                                                           │
│  ... (更多任务工作区)                                     │
│                                                           │
│  自动清理：超过 7 天的工作区启动时自动删除                 │
└─────────────────────────────────────────────────────────┘
```

**隔离机制**：

| 层面 | 机制 | 平台 |
|------|------|------|
| 进程隔离 | `sandbox-exec` (seatbelt) | macOS |
| 进程隔离 | `bwrap` (bubblewrap) | Linux |
| 文件系统 | 读范围白名单 + 写范围白名单 | 跨平台 |
| 网络 | 默认断网（`HARNESS_ALLOW_NETWORK` 控制） | 跨平台 |
| 工作区 | 每任务独立目录 | 跨平台 |

**读范围**：
- 项目目录（当前工作目录）
- 任务工作区
- 系统临时目录

**写范围**：
- 任务工作区（默认）
- `HARNESS_SANDBOX_ROOTS` 配置的额外目录

**系统提示注入**：
每次 LLM 调用前，系统提示会注入：
- 当前可写工作区路径
- 可写白名单列表
- 读取范围限制

模型不再瞎猜路径，减少越权操作。

**位置**：`src/skills.rs`

**设计**：对齐 Agent Skills 开放标准，通过 resolve-skills submodule 提供技能包。

```
技能加载流程
    │
    ▼
┌─────────────────────────────────────────┐
│  搜索顺序（优先级从高到低）               │
│                                          │
│  1. $HARNESS_SKILLS_DIR (环境变量)      │
│  2. <cwd>/.resolve-tui-skills/          │
│  3. ./resolve-skills/skills/ (submodule)│
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  技能结构（SKILL_SPEC 契约）             │
│                                          │
│  skills/                                 │
│  └── <skill-name>/                       │
│      ├── SKILL.md  (必需)                │
│      │   ├── frontmatter                 │
│      │   │   ├── name                    │
│      │   │   ├── description             │
│      │   │   └── triggers (可选)         │
│      │   └── 指令正文                    │
│      ├── scripts/  (可选)                │
│      ├── references/ (可选)              │
│      └── assets/ (可选)                  │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  激活方式                                 │
│                                          │
│  - 有 triggers：关键词命中时注入正文      │
│  - 无 triggers：常驻模型自选              │
│  - 模型调用 skill-run 工具加载完整指令    │

```

**内置技能**（来自 resolve-skills submodule）：

| 技能 | 职责 |
|------|------|
| code-review | 代码审查，输出结构化报告 |
| post-comment | WordPress 站点随机文章评论 |
| rust-review | Rust 代码质量审查 |
| weekly-investment-review | 投资组合周报生成 |

## 6. MCP 集成

**位置**：`src/mcp/`

**设计**：动态添加/移除 MCP 服务器，扩展 agent 工具能力。

```
MCP 架构
    │
    ▼
┌─────────────────────────────────────────┐
│  MCP 管理器 (manager.rs)                 │
│  - 服务器生命周期管理                      │
│  - 工具注册与注销                          │
│  - 配置持久化 (config.toml)              │
└────────────────────┬────────────────────┘
                     │
         ┌───────────┼───────────┐
         ▼           ▼           ▼
    ┌─────────┐ ┌─────────┐ ┌─────────┐
    │ MCP 服务器1│ │ MCP 服务器2│ │ MCP 服务器3│
    │ (stdio)  │ │ (stdio)  │ │ (stdio)  │
    └────┬────┘ └────┬────┘ └────┬────┘
         │            │            │
         ▼            ▼            ▼
    ┌─────────────────────────────────────┐
    │  MCP 客户端 (client.rs)              │
    │  - JSON-RPC 2.0 协议                 │
    │  - 工具调用转发                       │
    │  - 结果解析                           │
    └──────────────────┬──────────────────┘
                       │
                       ▼
              Agent 工具调用循环
```

**核心组件**：

| 组件 | 文件 | 职责 |
|------|------|------|
| 协议 | `protocol.rs` | MCP JSON-RPC 2.0 消息定义 |
| 客户端 | `client.rs` | stdio 传输，工具调用 |
| 管理器 | `manager.rs` | 服务器生命周期，工具注册 |

**TUI 命令**：
- `/mcp add <name> <command> [args...]` — 添加服务器
- `/mcp remove <name>` — 移除服务器
- `/mcp list` — 列出已配置服务器

**示例**：
```bash
# 文件系统 MCP
/mcp add fs npx -y @modelcontextprotocol/server-filesystem /path/to/dir

# GitHub MCP
/mcp add gh npx -y @modelcontextprotocol/server-github
```

## 7. 配置系统

**位置**：`src/config/`

**设计**：TOML 文件 + 环境变量表驱动合并，环境变量优先。

```
配置加载流程
    │
    ▼
┌─────────────────────────────────────────┐
│  1. 加载 .env (dotenvy)                 │
│     - 项目根目录 .env                    │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  2. 加载 TOML 配置 (file.rs)            │
│     - config.toml (可选)                 │
│     - MCP 服务器配置                      │
│     - 工具启用/禁用配置                   │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  3. 合并配置 (mod.rs)                    │
│     - 环境变量优先于 TOML                 │
│     - 默认值兜底                          │
│     - 类型校验 (serde)                   │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  4. 运行时配置对象                        │
│     - api_key, base_url, model           │
│     - sandbox, multi_agent, skills_dir   │
│     - max_iterations, max_tokens         │
│     - mcp_servers, tools_enabled         │
└─────────────────────────────────────────┘
```

**配置来源优先级**：
1. 环境变量（最高优先级）
2. TOML 配置文件
3. 代码默认值（最低优先级）

**关键环境变量**：见 README.md 环境变量表。

## 8. 会话与记忆

**位置**：`src/sessions.rs`, `src/memory.rs`

### 8.1 会话管理

**设计**：退出自动存档，启动自动续接，支持多会话切换。

```
会话目录：.resolve-tui-sessions/  (HARNESS_SESSIONS_DIR 覆盖)
    │
    ├── session-<timestamp>.json   # 会话存档
    ├── session-<timestamp>.json
    └── ...
```

**会话内容**：
- 消息历史（用户/助手/工具调用）
- 系统提示快照
- 模型配置
- 沙箱工作区路径

**TUI 命令**：
- `/list` — 列出所有会话
- `/create` — 创建新会话
- `/apply <id>` — 切换到指定会话
- `/save` — 手动保存当前会话
- `/load <id>` — 加载指定会话
- `/clear` — 清空当前会话
- `/rm <id>` — 删除指定会话
- `/export` — 导出会话为文件

### 8.2 跨会话记忆

**设计**：`/remember` 命令将重要信息写入长期记忆，跨会话复用。

```
记忆文件：MEMORY.md  (系统配置目录，权限 0600)
    │
    ├── 项目特定信息
    ├── 用户偏好
    ├── 常用命令
    └── ...
```

**特点**：
- 系统提示自动注入 MEMORY.md 内容
- 文件权限 0600，仅当前用户可读
- 不入库，保护隐私

## 9. 数据流

### 9.1 CLI 模式数据流

```
命令行参数
    │
    ▼
main.rs ──▶ agent::cli::run()
                │
                ▼
          配置加载 (config)
                │
                ▼
          沙箱初始化 (sandbox)
                │
                ▼
          技能加载 (skills)
                │
                ▼
          ┌───────────────┐
          │ 三级响应链      │
          │ fastpath       │
          │   ↓ (未命中)   │
          │ codegen        │
          │   ↓ (未命中)   │
          │ LLM 主循环      │
          └───────┬───────┘
                  │
                  ▼
            输出到 stdout
```

### 9.2 TUI 模式数据流

```
用户输入 (crossterm)
    │
    ▼
tui::app::input.rs ──▶ 命令解析 (commands/)
                            │
                ┌───────────┼───────────┐
                ▼           ▼           ▼
          内置命令      会话管理      普通消息
          (/pse, /mcp)  (/list,/save)    │
                │           │           │
                └───────────┼───────────┘
                            │
                            ▼
                      agent 主循环
                            │
                            ▼
                  流式输出 (render.rs)
                            │
                            ▼
                      终端显示 (ratatui)
```

## 10. 扩展点

### 10.1 添加新技能

1. 在 resolve-skills 仓库创建 `skills/<name>/SKILL.md`
2. 遵循 SKILL_SPEC 契约（frontmatter + 指令）
3. 可选添加 `scripts/` 辅助脚本
4. 更新 submodule：`git submodule update --remote`

### 10.2 添加新 fastpath

1. 在 `src/fastpath/` 创建新模块（如 `currency.rs`）
2. 实现 `detect()` 和 `execute()` 函数
3. 在 `src/fastpath/mod.rs` 注册

### 10.3 添加新 codegen 插件

1. 在 `src/codegen/plugins/` 创建插件
2. 实现插件 trait（匹配、执行、学习）
3. 在 `plugins/registry.rs` 注册

### 10.4 添加新 MCP 服务器

运行时动态添加：
```bash
/mcp add <name> <command> [args...]
```

或在 `config.toml` 中静态配置。

### 10.5 添加新内置工具

1. 在 `src/tools.rs` 定义工具
2. 实现工具执行逻辑
3. 在工具注册表中注册
4. 更新系统提示中的工具列表

## 11. 安全与隐私

### 11.1 安全机制

| 机制 | 位置 | 说明 |
|------|------|------|
| 沙箱隔离 | `sandbox.rs` | 进程级隔离，默认断网 |
| 文件范围限制 | `sandbox.rs` | 读/写白名单，防越权 |
| 每任务工作区 | `sandbox.rs` | 任务间互不影响 |
| 工具审批 | `agent/` | `HARNESS_APPROVE_TOOLS` 交互式审批 |
| 迭代上限 | `agent/drive.rs` | `HARNESS_MAX_ITERATIONS` 防死循环 |
| Token 预算 | `llm.rs` | `HARNESS_MAX_TOKENS` 成本控制 |

### 11.2 隐私保护

| 数据 | 存储位置 | 权限 | 入库 |
|------|----------|------|------|
| API Key | 环境变量 / 钥匙串 | — | ❌ |
| .env | 项目根目录 | — | ❌ (.gitignore) |
| 会话存档 | `.resolve-tui-sessions/` | 0600 | ❌ |
| 长期记忆 | `MEMORY.md` | 0600 | ❌ |
| 沙箱工作区 | `.resolve-tui-sandbox/` | — | ❌ |
| MCP 配置 | `config.toml` | 用户自定 | ⚠️ 注意 token 明文 |

### 11.3 数据外发边界

**会随 LLM 请求外发的数据**：
- 任务全文
- 注入的 `AGENT.md` / `MEMORY.md`
- 工具参数与命令输出
- 读取的文件内容

**不会外发的数据**：
- API Key（仅用于鉴权 header）
- 未被读取的本地文件
- 会话存档（除非模型主动读取）

## 12. 性能优化

### 12.1 响应延迟

| 路径 | 典型延迟 | 说明 |
|------|----------|------|
| fastpath | <10ms | 纯本地计算 |
| codegen (命中) | <50ms | 缓存执行 |
| codegen (未命中) | 2-5s | 便宜模型生成 + 验证 |
| LLM (单轮) | 1-10s | 取决于模型和输出长度 |
| LLM (多工具) | 10-60s | 多轮工具调用循环 |

### 12.2 成本控制

| 机制 | 说明 |
|------|------|
| fastpath | 零成本，优先匹配 |
| codegen 缓存 | 首次生成后零成本 |
| 分层模型 | codegen 用便宜模型，主循环用强模型 |
| Token 预算 | `HARNESS_MAX_TOKENS` 硬上限 |
| 迭代上限 | `HARNESS_MAX_ITERATIONS` 防无限循环 |
